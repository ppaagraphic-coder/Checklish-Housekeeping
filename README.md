# ระบบตรวจห้องพัก (เอกสารภายใน)

เว็บแอปตรวจรายการของใช้ในห้องพัก 25 รายการ ตรวจต่อเนื่อง 3 ขั้น แล้วแจ้งคนถัดไป
ใช้บนมือถือและแท็บเล็ต โฮสต์บน GitHub Pages เก็บข้อมูลและ log ใน Google Sheet

```
มือถือ/แท็บเล็ต → GitHub Pages (docs/) → Google Apps Script (apps-script/) → Google Sheet
```

## วิธีใช้งานในโรงแรม

| บทบาท | ทำอะไร |
|---|---|
| หัวหน้าฝ่ายต้อนรับ | กด **แขกเช็กอิน / เช็กเอาท์** ที่แท็บ "ห้องพัก" และตรวจขั้นสุดท้าย (QC) |
| แม่บ้านประจำชั้น | เห็นและทำได้เฉพาะ **ชั้นของตัวเอง** (ตามคอลัมน์ `floors` ของบัญชี) เห็นห้องที่เช็กเอาท์ → กด **ทำเสร็จแล้ว** → ตรวจขั้น 1 → ถ้าพบปัญหาแก้แล้วกด **แก้ไขแล้ว ส่งตรวจซ้ำ** |
| หัวหน้าแม่บ้าน | ตรวจขั้น 2 เลือกหลายห้องแล้วกด **ผ่านทั้งหมดที่เลือก** ได้ และเริ่มตรวจตามรอบเช้า/บ่าย |
| ผู้ดูแลระบบ | ดูภาพรวม ผังห้อง ห้องค้าง รายการที่พบปัญหา ประวัติ และยกเลิกใบตรวจที่เปิดผิด |

วงจรห้อง: `พร้อมขาย → มีแขกพัก → รอทำความสะอาด → รอตรวจ (ขั้น 1→2→3) → พร้อมขาย`
ทุกครั้งที่แม่บ้านกด "ทำเสร็จแล้ว" ระบบสร้างใบตรวจใหม่ ใบเก่าเก็บเป็นประวัติ ไม่ถูกเขียนทับ

กติกาสำคัญ
- ติ๊ก ✗ ที่ขั้นใด ห้องเป็น "มีปัญหา" และไม่ส่งต่อจนกว่าแม่บ้านจะแก้ จากนั้นตรวจซ้ำ **เฉพาะรายการที่มีปัญหา** ที่ขั้นเดิม
- เช็กอินห้องที่ยังตรวจไม่ครบ ระบบถามยืนยันก่อน ถ้ายืนยัน ใบตรวจที่ค้างถูกยกเลิกพร้อมบันทึกว่าใครทำ
- ตรวจตามรอบ (เช้า/บ่าย) เริ่มได้เฉพาะห้องว่างที่พร้อมขาย และห้ามซ้ำรอบเดียวกันในวันเดียวกัน
- ห้องค้างที่ขั้นใดเกิน 30 นาที ขึ้นสีแดงและเครื่องหมาย ! (ปรับได้ที่ `docs/config.js`)

## ลองก่อนติดตั้ง (โหมดทดลอง)

เปิด `docs/index.html` ผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ เช่น

```
cd docs && python3 -m http.server 8000     # แล้วเปิด http://localhost:8000
```

ถ้า `API_URL` ใน `docs/config.js` ยังว่าง จะเป็นโหมดทดลอง ข้อมูลจำลอง เก็บในเครื่อง มีแถบสลับบทบาทด้านบน

## ติดตั้งจริง (ประมาณ 20 นาที)

### 1) Google Sheet + Apps Script
1. สร้าง Google Sheet ใหม่ ตั้งชื่อว่า "ตรวจห้องพัก" (เจ้าของแชร์ให้เฉพาะคนที่จำเป็น)
2. เมนู **Extensions → Apps Script**
3. สร้างไฟล์ให้ตรงกับในโฟลเดอร์ `apps-script/` แล้ววางโค้ดทับ: `Code.gs`, `Core.gs`
   และเปิด Project Settings → ติ๊ก "Show appsscript.json" แล้ววางเนื้อหาของ `appsscript.json`
4. กด Save แล้วกลับไปที่ Sheet รีเฟรชหน้า จะมีเมนู **ระบบตรวจห้อง**
5. เมนู **ระบบตรวจห้อง → ตั้งค่าชีตครั้งแรก** (ครั้งแรกจะขอสิทธิ์ ให้กดอนุญาต)
   ระบบสร้างชีต 7 แผ่น และแสดง **PIN เริ่มต้นของ 8 บัญชี ให้จดไว้** (admin, แม่บ้านชั้น 1–5 ชั้นละ 1 คน รหัส maid01–maid05, หัวหน้าแม่บ้าน, หัวหน้าฝ่ายต้อนรับ)
6. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec`

> "Anyone" หมายถึงใครมี URL ก็เรียก API ได้ แต่ทุกคำสั่งต้องมี token ที่ได้จากการใส่ PIN ข้อมูลไม่ได้อยู่ในหน้าเว็บ

### 2) GitHub Pages
1. สร้าง repository ใน GitHub แล้ว push โฟลเดอร์นี้ขึ้นไป
2. แก้ `docs/config.js`: ใส่ `API_URL` (URL จากข้อ 1.6) และ `HOTEL_NAME`
3. Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / โฟลเดอร์ `/docs`
4. รอสักครู่ จะได้ URL `https://<ชื่อ>.github.io/<repo>/`
5. เปิดบนมือถือ → เมนูเบราว์เซอร์ → **เพิ่มไปยังหน้าจอหลัก** ใช้เหมือนแอป

ถ้าไม่อยากให้ repository เป็นสาธารณะ ใช้ repository แบบ private ได้ถ้าบัญชี GitHub รองรับ Pages แบบ private (แผนเสียเงิน)
ข้อมูลจริงไม่อยู่ใน repository อยู่แล้ว แต่ซอร์สโค้ดและ `API_URL` จะอยู่ จึงควรพิจารณาก่อน

### 3) จัดการผู้ใช้ ห้อง และรายการของใช้ (แก้ในชีตโดยตรง)
- **Users**: เพิ่มแถวใหม่ ใส่ `id` (a-z 0-9 _), `name`, `role` (`admin` / `maid` / `head_maid` / `reception`),
  `floors` (เฉพาะแม่บ้าน เช่น `1,2`), `active` = `1` แล้วใส่ PIN 4–6 หลักในคอลัมน์ `newPin`
  → เมนู **ระบบตรวจห้อง → นำ PIN ใหม่ในคอลัมน์ newPin มาใช้** (PIN ถูกแปลงเป็น hash แล้วลบช่อง newPin ทิ้ง)
- ปิดบัญชี: เปลี่ยน `active` เป็น `0`
- **Rooms**: แก้เลขห้อง/ชั้นได้ (ค่าเริ่มต้น 40 ห้อง = 5 ชั้น ชั้นละ 8 ห้อง เลข 101–108, 201–208 … 501–508) คอลัมน์ `status` ต้องเป็น `ready` ตอนเริ่มใช้
- **Items**: แก้ชื่อและจำนวนมาตรฐานของ 25 รายการได้ (อย่าสลับลำดับ `no` หลังเริ่มใช้งานแล้ว)

## ชีตที่ได้

| ชีต | เก็บอะไร |
|---|---|
| Users, Rooms, Items | ตั้งค่า |
| Inspections | 1 แถวต่อ 1 ใบตรวจ (รหัส ห้อง ประเภท สถานะ ขั้นปัจจุบัน เวลา) |
| Steps | 1 แถวต่อ 1 ขั้นที่ตรวจ (ใคร เมื่อไหร่ ครบกี่/พบกี่รายการ) |
| Issues | เฉพาะรายการ ✗ พร้อมหมายเหตุและสถานะแก้แล้วหรือยัง |
| Log | ประวัติทุกการกระทำ (ใคร ทำอะไร กับห้องไหน เมื่อไหร่) |

ทำ pivot/กราฟ หรือต่อ Looker Studio จากชีตเหล่านี้ได้เลย

## แจ้งเตือนคนถัดไป

- **ในแอป (พร้อมใช้ทันที):** แอปเช็กงานใหม่ทุก 25 วินาทีขณะเปิดอยู่ มีเลขแจ้งที่แท็บ เสียงเตือน และข้อความเด้ง
  ต้องเปิดแอปค้างไว้ ปิดหน้าจอ/สลับแอป เบราว์เซอร์อาจหยุดเช็ก
- **LINE (ไม่บังคับ แจ้งเตือนแม้ปิดแอป):**
  1. สร้าง LINE Official Account + เปิด Messaging API แล้วออก Channel access token (long-lived)
  2. Apps Script → Project Settings → Script properties เพิ่ม `LINE_TOKEN` = token ดังกล่าว
  3. ให้แต่ละคนเพิ่มบัญชีเป็นเพื่อน แล้วนำ LINE User ID ใส่ในคอลัมน์ `lineUserId` ของชีต Users
  4. ค่าเริ่มต้นส่งเฉพาะเมื่อ "พบปัญหา" เพื่อประหยัดโควตา ถ้าต้องการเพิ่ม ตั้ง `LINE_KINDS` เช่น `issue,next,fixed,checkout`
  
  ข้อความ push ของ LINE OA มีโควตาฟรีต่อเดือนจำกัด ตรวจแผนปัจจุบันของ LINE ก่อนเปิดชนิดที่ส่งถี่

## ความปลอดภัย

- GitHub Pages เปิดจากอินเทอร์เน็ตทั่วไป จำกัดเฉพาะ Wi-Fi โรงแรมไม่ได้ ระบบจึงป้องกันที่ฝั่ง API:
  PIN เก็บเป็น hash (SHA-256 + ค่าลับของโปรเจกต์), token หมดอายุ 12 ชั่วโมง, ใส่ PIN ผิด 5 ครั้งถูกล็อก 5 นาที
- สิทธิ์ตรวจทุกคำสั่งที่ฝั่ง Apps Script ไม่เชื่อสิ่งที่หน้าเว็บส่งมา
- เก็บเฉพาะข้อมูลของใช้ในห้อง ไม่เก็บข้อมูลแขก ใช้ PIN 6 หลักและเปลี่ยนเมื่อมีพนักงานลาออก
- ถ้าแก้โค้ด Apps Script แล้ว ต้อง **Deploy → Manage deployments → Edit → New version** URL เดิมจึงใช้โค้ดใหม่

## สัญญาณหลุด

กดส่งตอนไม่มีสัญญาณ แอปเก็บคำสั่งไว้ในเครื่อง ขึ้นป้าย "รอส่ง N" และส่งให้เองเมื่อกลับมาออนไลน์
(ส่งซ้ำปลอดภัย: ระบบกันการบันทึกซ้ำด้วยรหัสคำสั่ง) หากมีคนอื่นทำงานเดียวกันไปก่อน ระบบจะแจ้งว่ารายการนั้นถูกข้าม

## สำหรับผู้พัฒนา

```
docs/core.js        กฎ workflow ชุดเดียว ใช้ทั้งหน้าเว็บ โหมดทดลอง และ Apps Script
docs/app.js         หน้าจอ 4 บทบาท     docs/api.js   โหมดทดลอง/โหมดจริง + คิวส่งซ้ำ
apps-script/Code.gs API + อ่านเขียนชีต   apps-script/Core.gs  คัดลอกจาก core.js
```
- แก้กติกาที่ `docs/core.js` ที่เดียว แล้วรัน `node tools/sync-core.js` เพื่ออัปเดต `apps-script/Core.gs`
- ทดสอบ: `npm test` (กฎ workflow ใน `test/core.test.js` และการส่งเป็นชุดใน `test/batch.test.js`)

## ข้อจำกัดที่ควรรู้

- ไม่มี push แท้ (ใช้การเช็กทุก 25 วินาที หรือ LINE) ถ้าต้องการ push จริงหรือเกิน ~100 ห้อง ควรย้ายฐานข้อมูลไป Firebase/Supabase
- หน้าเว็บโหลดข้อมูลเฉพาะ 2 วันล่าสุด (รายการที่พบปัญหาย้อนหลัง 14 วันสำหรับ admin) ประวัติทั้งหมดดูในชีต
- Apps Script รันทีละคำขอ (LockService) ตอบกลับช้า 1–3 วินาที แต่หน้าจอแสดงผลทันทีที่กด แล้วส่งเบื้องหลังตามลำดับ คำสั่งที่กดติดกันระหว่างรอจะถูกรวมเป็นชุดเดียว (action `batch` ครั้งละไม่เกิน 30 คำสั่ง) ล็อก อ่าน และเขียนชีตครั้งเดียว ต้อง Deploy เวอร์ชันใหม่ของ Apps Script ก่อนใช้หน้าเว็บเวอร์ชันนี้ (ถ้ายังเป็นเวอร์ชันเก่า หน้าเว็บจะถอยกลับไปส่งทีละคำสั่งเองโดยไม่พัง) ถ้าเซิร์ฟเวอร์ปฏิเสธ (เช่น มีคนทำไปก่อน) หน้าจอจะแจ้งและโหลดข้อมูลจริงมาแทน
- แก้ชีต Users (เพิ่ม/ปิดบัญชี เปลี่ยนชั้น) จะมีผลภายใน ~1 นาที (ระบบจำรายชื่อผู้ใช้ไว้สั้น ๆ เพื่อความเร็ว)
- แม่บ้านที่ช่อง `floors` ว่าง จะไม่เห็นห้องและทำรายการไม่ได้ ให้ใส่เลขชั้น เช่น `2` หรือ `1,2`
- การจัดการผู้ใช้/ห้อง/รายการของใช้ทำในชีต ยังไม่มีหน้าจัดการในแอป
